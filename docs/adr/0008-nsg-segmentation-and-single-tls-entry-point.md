# 8. Subnet segmentation with NSGs and a single TLS entry point

Date: 2026-09-22

## Status

Accepted

## Context

Two things were wrong with the network even though the data services were
already private.

The subnets had no network security groups at all. Inside the VNet everything
could reach everything, so a compromised pod could open a connection straight to
the PostgreSQL subnet. Private endpoints do not help here: they keep the
internet out, not a neighbour in.

And the application was published as a `LoadBalancer` service on port 80. Plain
HTTP, a bare IP address, no certificate, with the frontend service itself owning
a public address.

## Decision

**Segmentation.** Each subnet gets an NSG whose last rule is an explicit deny:

| Subnet | Allowed inbound |
|--------|-----------------|
| `aks` | 80 and 443 from the internet, Azure load balancer probes, VNet-internal traffic |
| `postgres` | 5432, and only from the `aks` subnet prefix |
| `private-endpoints` | 443, 5671, 5672 and 10000, and only from the `aks` subnet prefix |

The private endpoint subnet also sets
`private_endpoint_network_policies = "NetworkSecurityGroupEnabled"`, because
private endpoints ignore NSGs unless policies are switched on — without it the
rules would be decorative.

Outbound stays at the Azure default. AKS nodes must reach the control plane,
Microsoft Container Registry and Entra ID; locking egress down properly means a
route table and Azure Firewall, and pretending an NSG does that job produces a
cluster that fails to start for reasons nobody enjoys debugging.

**Entry point.** ingress-nginx is installed from a pinned chart version by
Terraform, and it owns the only public address. The frontend service became
`ClusterIP`. One Ingress routes `/api` to the API and `/` to the frontend, with
`force-ssl-redirect` so port 80 exists only to send clients to 443.

The certificate is self-signed, generated by Terraform and written to the
`shoppulse-tls` secret. There is no registered domain for this project, so
Let's Encrypt cannot issue anything: a self-signed certificate is the honest
version of "TLS is wired up end to end". The Ingress references the secret by
name, so swapping in cert-manager with an ACME issuer later changes nothing
outside of `ingress.tf`.

## Consequences

The blast radius of a compromised pod is now bounded by the NSG rules, and the
public surface is one load balancer that speaks only HTTPS.

Three costs are worth stating. Clients need `curl --resolve` or a hosts entry to
reach `shoppulse.local`, and `-k` to accept the self-signed certificate — the
deploy smoke test does exactly that. AKS keeps its own NSG on the node network
interfaces, so a port has to be open in both places, and a rule missing here
looks exactly like an application hang. And enabling network policies on the
private endpoint subnet means a forgotten port shows up as a connection timeout
against a hostname that resolves perfectly.
